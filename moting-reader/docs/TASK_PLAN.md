# 墨听阅读器：完整任务规划

## 1. 产品目标

做一款个人使用、移动端优先、可安装的本地 PWA 阅读器。用户导入电子书后，可以阅读，也可以进入独立的“听书”界面选择书籍并连续朗读。

软件必须满足：

- 不登录也能使用。
- 不依赖 API Key 也能完成导入、阅读和系统语音朗读。
- 数据默认保存在当前浏览器中。
- 阅读位置和听书位置分别记录，并支持从当前正文位置开始听。
- 最终交付本地源码和使用说明压缩包，不进行线上部署。

## 2. 本次交付范围

### 2.1 书架

- 导入 EPUB、文字型 PDF、TXT、Markdown。
- 展示封面、书名、作者、格式、阅读进度和最近打开时间。
- 搜索、排序、删除书籍。
- 继续阅读。
- 显示导入、解析和错误状态。

### 2.2 独立听书页

- 继续上次收听。
- 浏览全部可听书籍。
- 搜索和筛选最近收听的书籍。
- 显示收听进度、当前章节和语音状态。
- 从列表直接进入播放器。

### 2.3 阅读页

- 章节目录。
- 上下章切换。
- 字号、行距、页边距、字体与主题设置。
- 当前朗读句高亮。
- 从任意句子开始朗读。
- 添加书签或听书标记。
- 阅读进度自动保存。

### 2.4 听书播放器

- 播放、暂停、前后一句。
- 上下章切换。
- 倍速。
- 语音选择。
- 睡眠定时。
- 查看当前文字。
- 逐句高亮和自动滚动。
- 听书位置自动保存。
- 一键标记当前句。

### 2.5 笔记与设置

- 汇总阅读书签和听书标记。
- 点击标记回到对应正文。
- 管理默认语音、倍速、主题和阅读排版。
- 查看本地数据说明。
- 清空演示内容或全部本地数据。

## 3. 核心数据模型

```text
Book
├── Chapter
│   ├── Paragraph
│   │   └── Sentence
│   └── ...
├── readingPosition
├── listeningPosition
└── metadata
```

关键原则：

- 原始展示文本和可朗读文本分开处理，但映射到同一句 ID。
- 阅读位置与听书位置分别保存，避免两种使用方式互相覆盖。
- 所有书签绑定稳定的书籍、章节和句子 ID。
- 语音按句子顺序播放，以句子边界作为暂停和跳转单位。

## 4. 文件导入策略

### EPUB

- 读取容器文件和 OPF。
- 提取 metadata、spine、封面和正文。
- 按书籍原有顺序生成章节。
- 清除脚本、样式、页眉页脚等不可朗读内容。

### 文字型 PDF

- 按页提取文本。
- 合并同一段落的断行。
- 清除纯页码和高频重复页眉页脚。
- 尝试识别章节标题。

### TXT / Markdown

- 使用文件名或首个标题作为书名。
- 识别 Markdown 标题和“第 X 章”样式。
- 没有目录时按文本长度安全分章。

### 本次不承诺

- 扫描 PDF OCR。
- DRM 保护的 EPUB。
- 复杂公式、双栏论文和高度定制排版的完全还原。

## 5. 听书实现策略

默认使用浏览器/系统提供的 Speech Synthesis：

- 无需账号和 API Key。
- 按句子创建朗读队列。
- 通过当前句索引实现逐句高亮、跳转和断点续播。
- 倍速在播放阶段调整。
- 语音列表由当前设备提供。

代码中保持语音服务边界，未来可以增加云端高质量 TTS，但本次交付不嵌入密钥，也不让用户在前端暴露密钥。

## 6. 本地存储

使用 IndexedDB 保存：

- 解析后的书籍和章节。
- 阅读位置与听书位置。
- 书签和听书标记。
- 用户设置。

原始文件不会上传到服务器。删除书籍时同步删除其内容和相关标记。

## 7. 视觉和交互标准

- 米白纸张背景、深墨色文字、灰蓝单一强调色。
- 正文使用适合中文阅读的系统衬线字体。
- 控件使用系统无衬线字体。
- 避免卡片堆叠、渐变、玻璃效果和装饰性 AI 元素。
- 移动端底部一级导航：书架、听书、笔记、我的。
- 所有高频触控区域不小于 44px。
- 支持 iPhone 安全区和桌面响应式布局。

## 8. 异常与边界状态

- 文件类型不支持。
- 文件过大或解析失败。
- EPUB 无目录或无封面。
- PDF 只有扫描图像。
- 当前设备没有可用语音。
- 朗读被系统中断。
- 删除正在播放的书籍。
- 当前章节为空。
- 浏览器存储不可用或空间不足。

每一种异常都必须给出用户可理解的状态，不显示底层技术错误。

## 9. 验收标准

- 示例书和用户导入书都能进入书架。
- EPUB、文字 PDF、TXT/Markdown 至少各有一条受测路径。
- 刷新页面后，书籍、进度、标记和设置仍然存在。
- 阅读与听书分别恢复到各自位置。
- 从正文任意句开始听时，播放器定位到同一句。
- 播放时当前句高亮，前后句控制准确。
- 修改倍速和语音后下一句生效。
- 定时关闭能够停止朗读。
- PWA manifest 和离线外壳可用。
- TypeScript、生产构建和项目测试全部通过。
- ZIP 中包含源码、安装说明、任务规划、测试记录和已知限制。

## 10. 实施顺序

1. 工程和数据模型。
2. IndexedDB 本地存储。
3. 文本、EPUB 和 PDF 解析。
4. 书架与导入流程。
5. 阅读页。
6. 独立听书页和播放器。
7. 笔记与设置。
8. PWA 和离线外壳。
9. 异常状态、响应式和可访问性。
10. 构建、测试、视觉检查、文档和打包。

## 体验升级：分阶段实施

在原有交付之上，围绕「听书操作响应及时、选区与菜单位置稳定、数据可靠」做三阶段升级。

### 第一阶段：听书与划线核心修复（已完成）

模块划分（对应「边界清楚的模块」这条要求）：

| 模块 | 文件 | 职责 |
| --- | --- | --- |
| 语音请求与缓存 | `lib/speech-cache.ts` | 按（文本, 音色）缓存、同段去重、消费者引用计数取消、预取并发上限、LRU 按 16 MB 预算淘汰 |
| 朗读分段 | `lib/speech-segments.ts` | 短首段 / 长批次的切分、章中起播的裁切、段内句子定位 |
| 播放控制 | `hooks/use-speech-player.ts` | 播放、暂停、定位、音色交接与失败恢复 |
| 菜单定位 | `lib/popover-placement.ts` | 上下翻转、安全区夹取、尖角指向、跨行选区取锚 |
| 正文选区 | `lib/text-selection.ts` + `hooks/use-text-selection.ts` | 位置模型、长按取词、跨句拆分、手柄拖动与边缘滚动 |
| 安全区测量 | `hooks/use-safe-insets.ts` | 用探针求值 `env(safe-area-inset-*)`，并合并键盘高度 |

几个关键决定：

- **音色切换不打断当前播放。** 先备好新音色的短首段，就绪后在句子边界交接，
  并按交接那一刻的真实播放位置 `seek` 过去。备好的那一段已经走出去了（跨段、跨章）
  就判定过期，按当前位置重新合成，绝不直接播旧音频。
- **交接必须复用预取时的锚点。** 合成结果按整段文本缓存，换个起始句就是另一个键，
  预取会白做。位置的推进改用时间轴反查 `timeAt()` 做 `seek` 补偿。
- **`priority` 只管排队，不代表不可取消。** 等结果的人全撤了照样掐掉上游，
  否则连点换音色会留下几条没人要的合成一直跑完。
- **菜单定位用量出来的真实尺寸。** 原来按固定半宽 104 px 夹取，而菜单实际接近 400 px，
  靠边的选区会把它挤出屏幕约 93 px。同时把第一层收敛成四项，常规宽度压到 294 px。
- **自定义选区只在触摸设备且能按坐标定位字符时启用**，否则退回系统选择——
  桌面上原生选择更好用，辅助阅读也需要它。

### 第二阶段：界面与播放体验完善（听书部分已完成）

自定义选区的跨段与已有划线处理、弹层与键盘焦点管理、视觉层级与触控区域、
阅读位置稳定性仍未开始。听书相关的几项（前后 15 秒按真实播放时间跳转、锁屏与中断恢复）
并进了下面的「听书第二轮」。音色只留云健一个，音色试听不做了。

### 听书第二轮：卡顿、停顿、断网与锁屏（已完成）

对照 Readest、edge-tts、Readium Speech 的实现查出来的问题，连同实测数据见 `TEST_REPORT.md`。

| 问题 | 原因 | 改法 |
| --- | --- | --- |
| 起播半分钟左右卡一次「正在准备」 | 首段读完直接接 4800 字长批次，长批次要整批合成完才回来（实测 40–48 秒） | 分三档：360 → 1500 → 全书网格（约 4000 字一格，可跨章），首段一开播就预取第二段 |
| 段落中间随机停一秒多，换段、换章反倒不停 | 每次合成结尾自带约 0.88 秒静音，拼接时原样保留；段落结构没传给 Worker | 用换行把段落/标题/章节带给 Worker，拼接时按帧裁掉多余静音、补数字静音帧 |
| 来电、拔耳机之后锁屏播放键按不动 | 没监听 `<audio>` 的 `pause` 事件，状态还是「在播」 | 监听元素事件同步状态；锁屏 play 一律走「继续」；回到前台再对一次账 |
| 偶尔断一次网，后面整本书都是机器音 | 失败一次就永久切到系统朗读；Worker 单片不重试 | Worker 单片重试 3 次；客户端先重试一次再降级，冷却后自动换回云端 |
| 偶发读到一半跳过一大段 | 连接提前断开也当成功，残缺音频被缓存一年 | 只认 `turn.end`；缓存键加版本号 |
| 「15 秒」其实是 ±2 句 | `skipSentences(±2)` | 按屏幕时钟在真实时间轴上跳；锁屏补上进度条和拖动 |
| 定时关闭到点后迷你条消失、后台可能延迟 | 30 分钟的 `setTimeout` + `stop()` | 记截止时间，播放进度回调里也检查；到点暂停；本章结束按目录项算 |
| 重开应用要重新合成，没网不能听 | 只有 16MB 内存缓存 | 本机 Cache Storage 持久缓存 + 「离线缓存后面 3 章」 |
| 多音字、人名读错没办法 | 无 | 设置里的「读音纠正」 |

模块划分：

| 模块 | 文件 | 职责 |
| --- | --- | --- |
| Edge 连接 | `worker/edge-tts.ts` | 握手、muid、空闲超时、只认 `turn.end`、错误分型 |
| 批量合成 | `worker/speech.ts` | 切片、并发、单片重试、422/503 分级、日志 |
| 切片与拼接 | `lib/speech-batch.ts` | 按段落优先切片、MP3 逐帧裁剪与补静音、时间轴拼接 |
| 分段 | `lib/speech-segments.ts` | 全书索引、三档分段、网格、跨章、读音替换、按秒估算跳转 |
| 持久缓存 | `lib/speech-persist.ts` | Cache Storage 存取、200MB LRU |
| 请求与缓存 | `lib/speech-cache.ts` | 内存 LRU、去重、预取并发、本机预热、离线下载 |
| 播放控制 | `hooks/use-speech-player.ts` | 状态同步、降级与回切、跳转、锁屏、定时关闭、离线缓存 |

### 第三阶段：长期可靠性（未开始）

备份与恢复、保存异常与重试、更新与回退流程、性能统计与关键流程自动化检查。

流式语音暂不投入：微软首帧 0.5–0.85 秒就到，流式能把起播再提前两三秒，但 iOS 上
`<audio>` 播边下边生成的流要服务端支持 Range，MSE 在 Safari 上对 MP3 的支持也查不到
可靠结论，得先在真机上验证。真要把后台连续播放做到原生水平，路线是套一层原生壳用
AVPlayer（Readest 在 iOS 上就是这么做的）。
