# 推荐与榜单轮换

用户希望每次逛书能发现不同作品，包括旧书。实现基于 `master` 的 `da7f7c5`，复用现有 11 类书目（1334 条分类记录、1316 个书籍 ID），没有按出版时间限制候选。

## 行为

- 首页、书城共享一批 20 本推荐。一次只展示前 8 本，横滑、展开后才会记录真正看见的作品。
- 从整个静态书池挑选。实际阅读/收听进度、至少 30 秒的阅读会话和近期详情点击提供兴趣信号；只导入、只打开文件不会直接作为已阅读偏好。
- 同一作品的营销后缀、国别与标点归一后去重，优先保留评分人数较多的版本。本地已入库作品和“不感兴趣”作品退出推荐，反馈可撤销。
- 可见面积至少一半且连续停留 800ms 记一次曝光；屏幕外、隐藏页面、后台和预加载不算。同一作品一天只记一次；最近 7 天曝光的作品排在未曝光和冷却到期作品之后，连续忽略进一步降权。
- 每批限制同题材、同作者占比，并交错题材，让首页前 8 本也保持多样。主动换批排除整个当前批次，候选不足时显示实际状态。
- 快照按本地日期轮换；同日切页、设置返回和刷新保留当前批次。应用从后台回来跨日时更新，阅读中的正文不受影响。
- 书城增加口碑、热读、小众口碑三种视角。口碑榜至少 500 人评价，按推荐值排序；热读榜按快照在读人数排序；小众口碑要求 500～9999 人评价、推荐值至少 85%。同分优先评分人数，再按书籍 ID 稳定排序。
- 首页按日轮换分类和榜单区段，支持“换个榜”；书城支持“换一组”和完整榜。选看区段仍显示其在完整榜中的实际名次，完整榜从第 1 名开始。

## 数据、缓存与范围

分类 JSON 最多三路并行加载，同一浏览会话复用结果，换批不会请求上游推荐接口。部分分类失败时使用成功部分并显示降级状态；全部失败时显示错误与重试入口，不生成假书目。评分与在读人数仍是原始快照数据，页面不会称它们为实时数据。

曝光、点击与隐藏反馈仅存当前浏览器的版本化 localStorage，最多保留 2000 条；普通行为保留 90 天，隐藏反馈优先保留。无法持久化时使用本次会话内存并记录 `store_feedback_storage_unavailable`。旧推荐快照不再继续固定首页。

本次没有新增依赖、书源、采集任务、云端行为画像或推荐服务；听书、阅读、同步和 AI 的实现保持原有代码。后续扩充书池可以独立进行。

## 验证

- `npm run typecheck`、`npm run lint`、`npm run build` 及 Cloudflare 产物校验通过。
- `node --experimental-strip-types --test tests/*.test.*`：362/362 通过，包括原有听书、同步和 AI 测试。初次运行的三个 HLS 文件因 `ffmpeg` 不在 PATH 失败；复用本机已安装的 FFmpeg 8.1.1，仅为测试进程补充 PATH 后完整通过，未改测试验收条件。
- `npx wrangler deploy --dry-run --config dist/server/wrangler.json`：通过，原有 D1、R2、Queue 和静态资源绑定齐全。
- `python tests/store-discovery-browser.py http://127.0.0.1:5178`：41 项通过，覆盖 375/390/430px、宣纸/墨夜、横滑曝光、隐藏页不曝光、连续换批无重复及布局位移、同日刷新稳定、主页与书城共享、三类榜单与完整名次、反馈撤销、设置返回位置、跨日轮换、部分/全部数据源失败，页面错误为 0。
- 纯逻辑测试使用仓库真实书池连续选择 20 批共 400 本，无重复作品，首页前 8 本覆盖至少 3 种题材。首页跨日选看名次逐项与完整榜比对。

浏览器测试使用真实分类 JSON，封面和书籍详情使用明确的测试夹具；没有向生产账户写数据。这些是 Edge/Chromium 手机视口测试，不代表 iPhone 真机验收。日志和截图保存在忽略目录 `.wrangler/discovery-rotation-tests/`。
