# 墨听阅读器：测试记录

## 测试范围

本记录对应本次源码包，目标是验证本地导入、阅读、独立听书流程、持久化、PWA 配置和生产构建。

## 自动化检查

交付前执行以下命令：

```bash
npm run typecheck
npm run lint
npm test
npm run deploy:dry-run
```

覆盖内容：

- TypeScript 严格类型检查。
- ESLint 代码规范检查。
- 生产构建和构建产物结构校验。
- 中文句子切分与可朗读文本清理。
- 章节识别、跨章节移动和 0–100% 进度计算。
- PWA manifest、192/512/maskable 图标和离线外壳入口。
- SpeechSynthesis、IndexedDB、独立听书路由和导入格式契约。
- 服务端渲染入口与正式 PWA metadata。
- Cloudflare Worker 入口、静态资源目录、兼容配置和上传包。

## 浏览器交互验证

在桌面 Chromium 预览环境中手动验证：

- 首次进入自动生成演示书，刷新后仍在书架。
- 书架和独立“听书”页可互相切换。
- 从听书书单进入播放器，并可打开当前文字。
- 从播放器进入完整正文，阅读器目录和上下章控件可用。
- 点击正文句子后，选中状态准确更新。
- 添加标记后刷新页面，标记仍然存在。
- TXT 文件导入成功；首行识别为书名，“第一章”识别为章节。
- EPUB 测试书真实导入成功；书名、作者、两个 spine 章节与正文顺序正确。
- 带可选择文字层的 PDF 测试书真实导入成功；metadata 书名、作者与正文提取正确。
- 删除测试书后，书架同步更新。
- 桌面侧栏和移动端底部导航采用同一信息架构。

## 已知限制

- 云端预览容器没有稳定的设备系统语音，不能据此评价音色或后台连续性；声音与可用语种必须在目标手机/电脑上验证。
- iOS 可能在锁屏、切到后台或省电模式下暂停网页语音，PWA 不能保证与原生音频播放器相同的后台策略。
- 扫描 PDF 暂不含 OCR；双栏、公式密集或复杂排版 PDF 的段落还原可能不理想。
- DRM EPUB 无法解析。
- 本版不含云端同步、书库导出、跨设备迁移或云端高质量 TTS。
- 数据依赖浏览器本地存储，清理站点数据会删除书库。

## 建议的真机验收

在目标 iPhone、Android 和桌面浏览器分别检查：

1. 安装到主屏幕。
2. 导入一册真实 EPUB 和一册真实文字 PDF。
3. 选择中文系统语音，以 1.0×、1.25×、1.5× 连续播放至少十分钟。
4. 测试锁屏、耳机控制、来电/闹钟打断后的恢复行为。
5. 关闭并重开应用，确认阅读与听书位置分别恢复。

## 浏览器实测

环境：Chromium，375×812 移动端模拟（`pointer: coarse`，`caretRangeFromPoint` 可用），
本地 `npm run dev`，`/api/tts` 走真实 Edge 合成。

### 听书

| 场景 | 结果 |
| --- | --- |
| 起播短首段（342 字） | 冷合成 3755 ms 后出声，随后自动预取 3009 字长批次续播 |
| 打开音色面板 | 触发 2 条并发预取（并发上限生效，第 3 条排队） |
| 切到已预取音色（缓存命中） | **38 ms** 完成交接，听书位置第 8 句 → 第 8 句，无倒退 |
| 切到未预取音色（冷合成） | 2.1–7.2 s，期间原音色继续播放，界面显示「切换中」 |
| 连点三个音色 | 只有最后一次生效，界面只剩一个「正在播放」 |
| 暂停时换音色 | 不自动起播，位置不动；恢复播放时用的是新音色 |
| 「选中」与「正在播放」 | 两者分开显示，自动模式下勾在「自动选择」、播放标在「晓晓」 |

单次云端合成耗时实测区间：**1.3 s – 7.2 s**（同一网络、同一段落，波动来自上游连接建立）。
因此 1 秒目标只在缓存命中路径成立，冷合成路径按实测如实报告。

## 未验证项

以下内容必须在真机确认，本轮不作结论：

- **iPhone 真机的自定义选区手感**：长按时长（460 ms）、移动容差（10 px）、
  手柄触控抬升（14 px）三个参数是按桌面模拟定的初值，需要在真机上调。
- **iOS WebKit 是否彻底不弹系统菜单**：模拟环境已确认 `user-select: none` 生效，
  但 WebKit 的长按行为与 Blink 不同，必须在主屏幕 PWA 里复核。
- **iOS 的中文分词质量**：`Intl.Segmenter` 在 Chromium 下会把「可以 / 进入 / 通勤」
  切成词、把「听 / 书 / 则」切成单字；WebKit 的切分边界未必一致。
- **锁屏连续播放、耳机与控制中心、来电中断恢复**：无真机不可测。
- **点击到出声的真实延迟**：上表的 38 ms 量到的是「音频交给 `<audio>` 元素」那一刻，
  真机上还要加解码与音频会话切换的开销。

## 工具环境限制

- Browser 面板在本次会话中处于隐藏状态，截图与点击工具全部超时，
