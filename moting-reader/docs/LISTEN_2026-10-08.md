# 听书改进移植到线上分支（2026-10-08）

线上跑的是本分支的连续音频（原生 HLS + Queue）架构。master 上那一版听书改进（PR #21）是按旧的分段播放器写的，这次把其中线上还没有的部分移植过来，架构以线上为准。

## 移植了什么

- **合成可靠性**：Edge 连接加 `muid`、10 秒无消息算超时；单片失败换条连接重试（最多 3 次，带抖动）；`/api/tts` 读不出来的文本回 422、服务问题回 503 并写日志。连续音频的 Queue 任务也用同一套单片重试，全是符号的片直接补静音、不送去合成。
- **停顿**：文字带结构（format 2：段落、标题、换章用 1/2/3 个换行），拼接时按帧裁掉每片结尾多余的自带静音、需要时补静音帧：句末约 0.66 秒、换段 0.8、标题 1.1、换章 1.8。新客户端建会话、调 `/api/tts` 都带 `format: 2`；老客户端不带，Worker 照旧处理，缓存键按 format 分开，互不串。
- **老路径分段**：起播 360 字、开播就预取 1500 字，之后 4800 字一批（以前是 360 字直接接 4800 字，长批次合成要四十多秒，起播半分钟左右必卡一次）。
- **系统打断**：来电、Siri、拔耳机只会暂停 audio 元素、不通知页面。以前连续音频在 pause 事件里自动 `play()` 回去，锁屏的播放键因为状态还是「在播」按了没反应，拔了耳机还会外放；现在两条路都同步成暂停，锁屏、耳机的播放键接着放同一路音频。
- **云端失败**：先等 1.5 秒重试一次，再失败才用系统声音顶上；冷却 30 秒起翻倍、最多 5 分钟，冷却到点后系统朗读每读一块顺手试一次云端，通了下一块自动换回。以前一失败就整场都是系统声音，直到用户手动重新开播。
- **15 秒跳转**：按真实音频时间轴跳（以前是 ±2 句，长句短句差很多），锁屏进度条按目录项一章一章算、能拖（`seekto`）。
- **定时关闭**：到点暂停而不是停止（迷你播放条和位置都留着），加了 60 分钟，播放页显示倒计时；「本章结束后」按目录项算（续页算在内），在换章前的静音里停、位置挪到下一章开头。以前为了这个会强制退回分段播放器、不用连续音频。
- **读音纠正**：设置 →「朗读音色」→「读音纠正」，只改送去合成的文字。
- **系统音色**：退回系统朗读时优先挑公认好听的中文音色和本机音色；安卓上不再用 pause/resume 保活（安卓上 pause 等于结束）。

## 没有移植的

- master 那一版的本机持久缓存（Cache Storage）和「离线缓存后面 3 章」、全书固定网格分段：它们是为分段播放器设计的，跟线上的连续音频会话（音频在 R2、按会话生成）对不上，硬搬会多出一套并行的缓存。连续音频本身已经解决了后台换源的问题。

- `npm run lint`、`npm run typecheck`、`npm test`（含 build 和 Cloudflare 产物校验）：287 项单测全过。新增 `tests/speech-structure.test.ts`、`tests/worker-speech.test.ts`、`tests/live-hls-structure.test.ts`（结构化会话的 MPEG-TS 用 FFmpeg 完整解码）。
- `tests/speech-chapter-browser.mjs`：43 项浏览器检查全过（真实《豆棚閒話》文本 + Chromium 真解码 MP3；HLS 控制流程用 MP3 替身，不等于 iPhone 实测）。原来的「意外暂停自动续播」「本章结束后停止」两项按新行为改写成「意外暂停同步成暂停、按播放接着放同一路」「本章结束后暂停在下一章开头、用连续音频」；新增结构化文本、15 秒跳转、计时到点暂停、云端失败重试 → 系统声音 → 自动换回的检查。
